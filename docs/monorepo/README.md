# Rose monorepo

One repository, three applications, one install, one task graph. This documentation explains how the
workspace is wired and how to use it end to end without guessing.

## Quick path

1. `pnpm install` from the repo root (never inside a project). It also runs `prepare`, which installs
   the Husky Git hooks; `.npmrc` sets `engine-strict=true`, so a wrong Node version fails the install.
2. `pnpm dev` to start the web app and the API in parallel.
3. Mobile is separate: `pnpm --filter @rose/mobileRose start` (Expo dev server on port 8081).
4. `pnpm test` runs Vitest (web), Jest (mobile), and `go test` (API).
5. `pnpm quality` runs the duplication and unused-code gates.
6. Verify: API `http://localhost:8080/health`, web `http://localhost:3000`, Expo on
   `http://localhost:8081` (after step 3).

## Ground rules

- **Install from the root only.** One lockfile (`pnpm-lock.yaml`), one `node_modules` layout.
- **Add dependencies with a filter** so they land in the right `package.json`.
- **Never edit `node_modules` or the lockfile by hand.**
- **Node >= 22 and pnpm 10.33.4** are pinned in `package.json` (`engines`, `packageManager`). `.npmrc`
  (`engine-strict=true`) enforces the Node engine, while pnpm is selected via `packageManager`.
- **Windows first:** the API build emits `bin/server.exe`. See [03-api.md](./03-api.md) to port it.

## Generated files

These are generated locally, ignored by Git, and never committed:

| Path            | Generated by            | Notes                                                      |
| --------------- | ----------------------- | ---------------------------------------------------------- |
| `.atl/`         | local tooling           | scratch/cache state, safe to delete                        |
| `expo-env.d.ts` | Expo CLI                | types come from `expo/types` in `mobileRose/tsconfig.json` |
| `.cache/`       | Prettier (local and CI) | recreated on demand                                        |

`mobileRose/tsconfig.json` includes `expo-env.d.ts` so the generated declarations resolve; the actual
types are configured as `types: ["jest", "expo/types"]`. Run any Expo command to regenerate the file.
